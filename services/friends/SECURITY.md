# Security and data boundaries

No hosted service is active. This document records implemented controls and the remaining deployment boundary.

- Auth `/user` verifies every bearer before RPC or Storage acquisition. Active membership, ownership/current friendship, recipient scope, enabled course and snapshot state are rechecked in PostgreSQL. Desktop-supplied owner IDs/versions never establish authority.
- Raw metadata tables use FORCE RLS with client grants revoked. Security-definer RPCs have fixed search paths. Only server-role RPCs finalize uploads or release Storage ledger reservations. Client direct-table access stays blocked even if SELECT is accidentally granted. Restrictive Storage exclusions protect this bucket against permissive client policies; privileged service/admin credentials remain outside RLS protection.
- Invite codes contain two random UUIDs; only SHA-256 hashes are stored. Codes expire and have one explicit acceptance. No public member search. A friend sees a display name and shares addressed to them, not the publisher's original collection, source projects or local reflection.
- Native export uses `CardIdsLimit` over a bounded union of selected descendants. It never exports collection scheduling, review history or deck options. Real native import/export tests check unrelated media exclusion, identity-preserving updates and source integrity. The service operator and recipients can read published card/media content; this is **not end-to-end encryption**.
- Automatic publication requires a saved explicit opt-in bound to profile/account/service origin. QueryOp serializes collection inspection/export; network transfers run outside the collection queue. Profile shutdown cancels the client, clears memory tokens and invalidates callbacks. Session tokens are not sent to JavaScript or intentionally saved to disk. A request already in flight cannot be unsent; callbacks cannot apply it to another profile.
- Each upload is a unique snapshot object, one ticket attempt and a conservative ten-minute lease. Finalization requires exact byte count/hash and the current lease. A retry uses a new snapshot/object. Cleanup first atomically claims eligible rows as revoked, deletes private objects, then confirms/reduces reserved storage. Active leases cannot be reclaimed. Failed cleanup retains reservations and is not reported as deletion.
- Requests and local exported content are bounded. Streaming byte/SHA checks reject corruption, truncation and expansion. Native download writes a sibling temporary file, verifies package/hash/size, then atomically replaces only the user-chosen destination. It never silently imports. No redirects forward bearer tokens; URLs are fixed relative paths on the configured HTTPS origin.
- Native packages are still trusted-content imports, not sandboxed documents. Share/import material only with permission and people you trust. Card templates and other installed add-ons retain their own behavior. The new service does not inspect every template script or enforce content copyright.
- Revocation prevents new authorized downloads; it cannot retrieve already saved copies, clear a recipient's backups or stop bytes already being transferred. Native APKG import does not mirror deletions or silently resolve competing edits.

Local tests cover service authorization, RLS collisions, leases, versioning, cleanup, quotas, stream integrity, client shutdown and native export/import. Managed deployment, production concurrency, email, backup restore, provider controls and independent security review remain gates in HOSTING-REQUIREMENTS.md. Do not describe this prepared service as live or production-certified.
