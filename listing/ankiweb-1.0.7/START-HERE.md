# Prepare the AnkiWeb listing

Everything in this folder is prepared for the owner's future listing. Nothing here submits an upload or creates an account.

1. When your account can upload an add-on, open https://ankiweb.net/shared/addons/ and choose Upload.
2. Upload **Atelier-1.0.7.ankiaddon** from the handoff. Do not upload the source ZIP, evidence ZIP or full handoff ZIP.
3. Copy **title.txt** into the title field: **Atelier**.
4. Copy **description.html** into the description editor. If the editor only offers plain text or strips formatting, use **description.txt**. The description's image links point to this version's screenshots in the owner-approved public GitHub repository.
5. Use the field values in **listing-fields.json** for support/source links, license and compatibility. The AnkiWeb editor may use different labels; review its actual fields. Do not claim tested macOS, Linux or universal compatibility.
6. Preview the listing. Check the images, support link, version and downloaded file. The current account's eligibility, future upload form and upload acceptance have not been verified by this package.
7. Record the real numeric add-on code. Do not invent one. Keep using that same listing for later updates so users can use Anki's add-on update mechanism.

## Before making the listing public

Approve the exact installer hash and final preview. Verify the then-current AnkiWeb terms, upload limits and eligible account. Test the real listing download in a spare profile. For people already using the private `daedalus_atelier` package, verify the private-to-numeric-listing migration first, including preferences, widgets, clock state, source projects, masks and exam records. No automatic migration is claimed in this build.

The repository's public visibility was explicitly authorized by the owner for support. That does not publish the AnkiWeb listing or deploy the website. Public repository status and working screenshot URLs are verified in the final handoff receipt.
