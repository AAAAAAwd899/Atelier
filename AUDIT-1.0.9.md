# Atelier 1.0.9 navigation audit

Classification: local Anki desktop add-on, cumulative upgrade of accepted 1.0.8 and verified 1.0.2. Shared Daedalus standards and owner storage/consumer directives apply. This is the current project report; BRIEF-1.0.9.md is the shared audience/voice/art-direction brief.

Read-only inspection confirmed the installed owner add-on reports 1.0.3 while the accepted package source was 1.0.8. The installed Onigiri source includes native-toolbar hiding paths; its live collection-specific settings were not read or changed. The supplied Mac reference also includes macOS system menus and add-on menus that depend on installed add-ons. Atelier now provides its own complete native-action bar instead of depending on toolbar visibility. No third-party toolbar or preference is forcibly changed.

A new optional hierarchy view retains grid/list, sorting, search, normal deck overview, folder move/rename/share/options/study routes and Anki availability counts. Icons are bounded enum tokens, validated with deck IDs and stored in the existing profile preference file. Invalid token/HTML/URL values are discarded or rejected. No Anki cards, decks, media or schedules are mutated by choosing an icon. Existing profiles receive an empty optional map; no new migration is required.

Theme geometry is checked on rendered selections across light/dark worlds. Checkmark space is reserved and the chooser uses stable typography, scrollbars and grid geometry. Actual native Anki theme choices and icon persistence are exercised in an isolated generated collection. Desktop/compact browser states are inspected at full size. Existing artwork remains byte-preserved.

Early visual review caught legacy responsive rules stacking the action bar; those rules are isolated by the new workspace header class. The original CSS-scope assertion rejected the substring dialog-body; it now distinguishes the scoped class from an actual body selector while retaining the engine/card-scope exclusions. The existing world-suite assertion now expects the four exact native commands including the newly exposed Statistics route. Tour anchors are updated to the real header utilities. No functional assertion is waived.

Native testing is Windows Anki 26.09.3 with generated unsynced profiles. Owner data is never opened. Installed Onigiri source was inspected, but a full installed-Onigiri coexistence run was not performed after the owner requested browser-only work to avoid desktop windows appearing. Native toolbar-hidden behavior was explicitly tested in Anki. Do not claim universal third-party, macOS/Linux, hardware or uncoached novice acceptance.

Exact fresh test counts and runtime binding come from verification/verified.json, native receipts and the build/handoff files. Packaging validates extracted-runtime equality, safe ZIP contents, source parity and repeat builds, and exercises the new UI from the extracted installer. No stale candidate result is promoted as a final pass. Only source is eligible for the exact previously approved GitHub repository; no AnkiWeb upload, website deployment, visibility change or public binary publication is performed.

The desktop tour and IO attempts closed before completing every step; their performed checks are recorded separately and excluded from final native totals. After the owner requested no more desktop windows, the remaining tour (26 checks) and IO question/answer/grade/Undo (10 checks) completed using the installed Anki/Qt offscreen platform. This is actual Anki runtime evidence, not Windows-display or hardware acceptance. Final evidence separates 98 Windows native checks and 36 offscreen Anki/Qt checks. Completion guards now reject a partial native run even if its process exits successfully.
